Decision playground API

The app has two providers. Laya evaluates locally in a private Python worker. Jev uses the TypeSafe hosted API through the Go server.

Laya

  • GET /api/health — status for both models; optional ?model=english.
  • GET /api/ready — HTTP 200 when both models are warm; otherwise 503.
  • POST /api/predict — structured state and named questions.
  • POST /api/decide — original prompt, question, and options compatibility endpoint.

Jev

Put your TypeSafe API key in TYPESAFE_API_KEY in the root .env file, then restart the server. .env is ignored by Git. The key stays on the Go server; the browser never receives it.

  • GET /api/jev/health — reports the configured model and whether a key is present, without exposing the key.
  • POST /api/jev — sends the same state and question format to TypeSafe's POST https://api.typesafe.ai/v1/systemone.

Jev is hosted. The state and questions you submit in the Jev tab are sent to TypeSafe. Keep credentials and sensitive information out of sample inputs. The model defaults to jev-latest; set JEV_MODEL=jev-1.13.0 to pin that documented release.

Typed request format

Both providers accept a state and 1–8 named questions. Use choice for a defined set, score for ordered rubric levels, and noul for a yes/no probability. Jev evaluates each question independently against the shared state; combine those answers in your application code.

{
  "model": "jev-latest",
  "state": {"message": "Checkout has failed for most customers since 9:10."},
  "questions": {
    "team": {
      "type": "choice",
      "instructions": "Which team should own this issue?",
      "criteria": {"technical": "outages and software failures", "billing": "settlement and invoices"}
    },
    "page_on_call": {
      "type": "noul",
      "instructions": "Should the on-call engineer be paged now?"
    },
    "impact": {
      "type": "score",
      "instructions": "How broad is the customer impact?",
      "criteria": ["isolated", "some customers", "most customers"]
    }
  }
}

Jev returns one typed answer per question, including probabilities and confidence for Choice and Score. The response also includes token usage and the model version. Confidence is a signal, not a guarantee.

Laya request

Send Content-Type: application/json. The local model defaults to typed-decisions; use english to compare.

{
  "model": "typed-decisions",
  "state": {"message": "I was charged twice. Please refund me."},
  "questions": {
    "refund_requested": {
      "type": "noul",
      "instructions": "Does the customer request a refund?"
    },
    "department": {
      "type": "choice",
      "instructions": "Which team should handle this?",
      "criteria": {"billing": "payments and refunds", "technical": "bugs"}
    },
    "urgency": {
      "type": "score",
      "instructions": "How urgent is the message?",
      "criteria": ["low", "medium", "high"]
    }
  }
}

Laya's raw noul is P(true); the UI compares yes and no and highlights the winner. Scores use zero-based rubric levels. Use 2–8 choice or score criteria. Invalid JSON, duplicate keys, and invalid definitions return 422. Requests above 256 KiB return 413; a busy local model returns 429; an unavailable model returns 503.

Open the request and response panel in the playground to inspect the JSON with syntax highlighting.
